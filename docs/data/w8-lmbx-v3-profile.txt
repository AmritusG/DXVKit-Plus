Findings
1. v3 adds nothing measurable to DCT tiles: a DCT-only v3 stream decodes within 1% of v1 (15.01 vs
   14.86 ms). The "format overhead" W7 attributed to glow is not the format: it is palette tiles.
2. The entropy pass carries the whole regression (glow +0.42 ms/layer, graphics +0.45 ms/layer);
   tables, idct and output are unchanged.
3. v3's palette path itself is slower than v2's at equal tools (graphics: v3 no-ctx 9.25 vs 0.6.1
   6.89 ms; same tiles, same 16-colour palettes): per pixel it reads the row above back from device
   memory (scr), writes two device words, and every palette stream's thread runs inside a SIMD group
   whose other lanes are DCT/empty streams of neighbouring tiles (one dispatch, stream-major).
4. Per tool on graphics: ctx +0.1 ms, 64-colour palettes 0, edge alpha +2.1 ms (a serial second
   sweep of 1024 pixels with a device byte read each), quad +1.1 ms; on glow quad +2.6 ms.
5. Tables pass ~0.27-0.31 ms/layer in 0.6.1 and v3 alike (11 workgroups expand in parallel); not a
   v3 cost, but 16384-slot index tables (9 x 128 KB) make the palette decode's working set large.
6. Shader-level counters: Xcode's GPU capture replay (shader profiler: per-line cost, occupancy,
   registers) asks for an administrator password (Developer Tools Access) on this machine; not
   available to this session. Metal System Trace's counter set records only "RT Unit Active" without
   a custom template. Per-line attribution was therefore done by A/B kernel variants under Metal
   System Trace (IMPLEMENT log below).
