# W8 — LMBX bitstream v3: speed recovered, frozen, 0.7.0 shipped

## Answer in one line
v3 is frozen and 0.7.0 is shipped (main, tag v0.7.0). GPU decode recovered from W7's −21…−40% to:
- natural footage at 0.6.1's speed or faster;
- graphics −4% at 4K, −15% at 1080p.
Graphics with alpha stays lossless below LMB7's bytes. Publishing was first refused by the session's permission classifier; Amrit then approved each git command (below).

**Decision (Amrit, verbatim): "graphics at -15% (1080p) accepted as the price of v3".**

- **The whole regression was the entropy pass.** Each palette tile's 1024-symbol serial decode ran in the same SIMD groups as DCT streams.

## Results
- **Speed** (release `dxvkit-plus bench`, steps/s, 2 interleaved rounds, Arena running; 0.6.1 / W7 / 0.7.0):

  | clip | 0.6.1 | W7 | 0.7.0 |
  |---|---|---|---|
  | 16 x 1080p glow | 61.3-61.6 | 44.8-46.7 | **59.1-62.6** |
  | 16 x 1080p graphics | 141.9-142.5 | 85.4-86.0 | **120.2-121.3** |
  | 4 x 4K Shroomies | 107.1-108.5 | 76.2-77.0 | **115.6-115.8** |
  | 4 x 4K graphics | 144.3-147.4 | 125.8-128.3 | **140.4-140.8** |

  - Target "no palette tiles within 5%": met. Glow −1% (it does have palette tiles); Shroomies +7%; a DCT-only v3 frame is +1%.
  - Graphics 1080p missed: −15%. Profile: entropy 7.1 vs 5.2 ms per 16-layer step. The context-coded palette decode itself (8 tables, 4-neighbour contexts, 1024-step serial chain) is latency-bound. Format attempts to shorten the chain cost bytes and decoded no faster. No v3 feature cut.
- **Quality at LMB7's bytes vs W7 best** (`docs/data/w8-lmbx-v3-quality.txt`):

  | content | W7 best | 0.7.0 | note |
  |---|---|---|---|
  | graphics + alpha | lossless, 4339 B | lossless, 4444 B | |
  | graphics | 85.97 dB | lossless | better |
  | real alpha shown | 55.08 | 55.29 | better |
  | glow | 43.001 | 42.988 | dip: 1 rate step |
  | synthetic alpha shown | 50.35 | 50.85 | better (alpha palette) |
  | grain | 53.30 | 53.30 | equal |
  | detail | 21.016 | 20.991 | dip: 1 rate step |

  - Glow and detail are the dips: −0.013 and −0.025 dB, one rate-control step.
  - Bytes to match LMB7: 3,711 B shown (LMB7 5,204) and 3,243 B RGB (5,807).
  - Eye clip: lossless 60/60 at 6,505 B/frame (LMB7 9,371).
  - Colour guard ≤ 0.01.
- **Alpha palette kept:**
  - no measurable speed cost (Shroomies 4K busy 8.944 vs 8.943 ms);
  - +0.01% bytes;
  - +0.5 dB shown on synthetic alpha.
- **Frozen spec:**
  - `docs/LMBD.md` §11 is normative for v1/v2/v3, with §11.6a and decision LMBX-D4 in Amrit's words.
  - 5 CC0 v3 vectors (+ sidecar hashes). One is hand-built (quad + edge alpha; the encoder never picks it on procedural cards).
  - The v2 vectors' re-encode hashes now pin v3 files; v1 re-encodes are byte-identical to before.
- **Encoder:**
  - production `v3.rs` (prototype knobs and dropped tools gone; v2 writer removed; `--modes dct` → v1);
  - byte-identical at 1/3/8 threads (identity test, 13 vectors).
- **Fuzz:** 600 s, 9.6 M runs over v1+v2+v3 vectors, 0 crashes, 0 hangs.

## Deviations
1. **No Xcode shader profiler.** GPU capture worked (scratch tool), but replay in Xcode asks for an administrator password (Developer Tools Access), which this session cannot give. MST's counter set has only "RT Unit Active" without a custom template, and edited templates recorded nothing. Per-line attribution was done by A/B kernel variants under MST and timestamp queries.
2. **Two measurement errors, caught and redone:**
   - S1's first numbers came from a binary whose upload failed validation. The profiler now asserts GPU == CPU and zero wgpu errors before timing.
   - The per-step-sync method let the GPU drop to its Minimum clock (~25% of runs). It now submits back to back and reports GPU-busy.
3. **Vectors:** one is hand-built, since the encoder never chooses quad + edge alpha on CC0 content.
4. **Eye clips via ffmpeg** `prores_ks` 4444xq (as W6/W7).
5. **W7 prototype spec doc** kept on main, marked superseded.
6. **High load avg (18-29) from other sessions' compiles during benches:** CPU-side timings are affected, GPU-busy is not.
