# W10 — EXPLORE: adaptive transform sizes (DCT 8/16/32) in LMBX

Branch `w10-explore`, from main (0.7.0). Prototype only: nothing merged, no tag, no release.

## Answer in plain words
Adaptive transform sizes **do not help real footage enough to justify a v4**. On real Shroomies footage at LMB7's bytes they add only **0.0 to +0.07 dB** over a better 0.7.0 encoder. They cost about **+17–24% GPU decode time** on natural clips.

What does help real footage is something W10 found along the way: **choosing each block's step by rate-distortion**. That gives **+0.4 to +0.7 dB** at the same bytes, and it is an **encoder-only change that writes plain v3**: 0.7.0 decoders read it unchanged.

The 16/32 transforms are a large win only on synthetic content:
- Detail card: 20.99 → 26.27 dB (LMB7 21.86).
- Film grain: −6% bytes.
- Synthetic alpha: −11% bytes.

**Recommendation:**
- **Drop** the v4 transform sizes for now.
- **Ship** the RD step search as an encoder-only 0.7.x change, after its own eye test.

## What was built (prototype)
- **Bitstream v4.** v3 plus a transform map: one byte per tile.
  - `0` = sixteen 8x8 blocks, as v3.
  - Bit `q` set = quadrant `q` is one 16x16 block.
  - `16` = one 32x32 block.
  - Only on DCT tiles of 4:4:4 frames.
  - Spec: `docs/LMBD.md` §11.12c.
  - v1, v2 and v3 decode bit-exact: every vector and test passes. The refusal test's "future" version is now 5.
- **Integer transforms.** 16x16 and 32x32 inverses, built by v1's rule: basis `round(2048 cos)`, all entries from one 33-entry table.
  - Bounds proven inside i32 (one clamp on the first stage, which no picture reaches).
  - Precision against the float inverse: RMS 0.33 (16) and 0.36 (32) quarter code values; 8x8 is 0.43.
- **DC and quantisation.** The DC chain is kept at 8x8 scale, so the DC predicts across sizes. Dequant clamp and DC step scale with n/8. A block's step comes from the q-map nibble at its top-left position.
- **Encoder (`crates/dxvkit-plus-lmbd-enc/src/v4.rs`).**
  - Per tile, the rate-distortion choice of the 17 layouts: RDOQ per candidate block, the exact DC chain, v3's weights and lambda.
  - Region steps by rule, finest covered, or rate-distortion (`rd_q`); 8x8 steps by rate-distortion (`rd_q8`).
  - Colour guard on every block size.
  - Tiles with at most 64 colours keep 0.7.0's coding; without this, graphics lost losslessness (67–68 dB).
  - A frame whose map is all zero is written as v3.
  - CLI: `encode-lmbd --tsizes rule|rd|rd8`.
- **GPU.**
  - Large-block tiles' streams decode in their own entropy workgroups, so the 8x8 path is untouched (W8's pattern).
  - New `idct_big` pass: one 64-lane workgroup per 16/32 block, with basis, coefficients and first stage in workgroup memory.
  - The 8x8 IDCT skips large blocks' areas behind a uniform `v4` branch.
  - Bit-exact with the CPU on 32 encoded and 128 hostile v4 frames (random data, random and all-32x32 layouts, empty streams). That is 1,065 tiles with 16x16 quadrants and 1,509 tiles with a 32x32 block.
- **Fuzz.** 600 s on v1–v3 vectors plus 4 v4 files: 2.42 M execs, 0 crashes, 0 hangs (`docs/data/fuzz-lmbx-v4-600s.txt`).
- **Fixed on the way:** the float reference decoder read v3 alpha-palette A streams as DCT blocks. That decoder is informative only.

## DIAGNOSE — the honest ceiling (`docs/data/w10-lmbx-ceiling.txt`)
W9's estimate was re-run with all three planes, LMBX's coding (zigzag + EOB, one table, DC chain) and the transform map's signalling. Gain at equal bytes, one step per frame:

| content | W9 estimate | W10 ceiling |
|---|---|---|
| real detail | +1.3 to +1.8 dB | +1.6 to +2.9 dB |
| glow | +0.3 to +0.7 dB | +0.1 to +1.4 dB |
| grain | +0.1 dB | +0.9 to +2.0 dB (smooth chroma planes) |
| detail card | — | +5.3 to +6.1 dB |

- At LMB7's (high) rates the gains shrink: about +0.5 dB on real detail and +0.1 dB on glow.
- Per-size coefficient tables add only about +0.1 dB, so v4 keeps one table.

## MEASURE

### Quality at LMB7's bytes
Source: `docs/data/w10-lmbx-quality.txt`. Values are shown PSNR (= RGB without alpha). "Ladder" = the best frame at or under the budget from a fine quality scan, which removes rate control's step walls.

- **control** = rate-distortion steps, 8x8 only; it writes v3.
- **W10** = transform sizes + rate-distortion steps.

| content | 0.7.0 | control | W10 | sizes add |
|---|---|---|---|---|
| real detail (ladder) | 54.99 | 55.56 | 55.58 | +0.02 |
| real alpha (ladder) | 55.34 | 55.77 | 55.74 | −0.03 |
| glow (ladder) | 42.91 | 43.32 | 43.39 | +0.07 |
| detail card (ab) | 20.99 | 21.37 | **26.27** | +4.9 (LMB7 21.86) |
| grain (ab, q 1 for all) | 364,242 B | same | **340,745 B** (−6.5%) | +0.11 dB too |
| synthetic alpha (ab, q wall) | 350,916 B | 348,284 B | **312,879 B** (−11%) | RGB equal; A 77.95 → 69.18 |
| graphics / graphics+alpha | lossless 5223 / 4444 B | same | **same: lossless, byte-identical** | 0 |

- **Colour guard holds** on every arm: worst flat-region error 0.00–0.04 code values (tolerance 1.0).
- **Against W9's estimate:** real detail +0.02 dB measured against +1.3–1.8 estimated; glow +0.07 against +0.3–0.7; grain only fewer bytes, as its budget already reaches q 1.
- **Pure transform effect:** with one step for every block, W10 against 8x8 on real detail is about +0.5 to +0.9 dB at equal bytes. That is about half the ceiling. LMBX's per-block step rule already takes most of what larger transforms would give.
- **Without the ≤ 64-colour rule:** sizes added about +0.17 dB on real alpha content, but graphics was no longer lossless. The rule stays.

### GPU decode speed
Source: `docs/data/w10-lmbx-speed.txt`. W8 method, median of 3, GPU == CPU asserted. Values are busy ms per step.

| clip | 0.7.0 file, 0.7.0 shader | 0.7.0 file, W10 shader | W10 file |
|---|---|---|---|
| glow 16×1080p | 64.1 | 65.4 | 79.4 (**+24%**) |
| Shroomies 4×4K | 27.8 | 29.3 | 32.5 (**+17%**) |
| graphics 16×1080p | 38.5 | 40.2 | 39.6 (identical file) |

- **Not valid as absolute numbers.** The Metal System Trace over 14.7 s shows the GPU never idle:
  - Blender held it 98% of the window.
  - WindowServer 52%, Arena 48%.
  - Our runs 39% and 30%.
- Arena and Blender were Amrit's sessions and were left running.
- **The DCT-8 path is within noise** (+2–5% against ±20% run-to-run).
- **The cost is the large-block inverse.** The idct pass goes 16 → 35 ms on glow: a 32-point matrix multiply does 4× an 8x8's work per pixel. An even/odd butterfly split would halve that and stay exact, since the sums are integer. Not tried.

### Complexity in plain words
- **Decoder:** one more map byte per tile, a 33-number cosine table, two more transform sizes, and a generalised zigzag.
  - About +240 lines in the CPU decoder and +210 in the GPU decoder, of which ~70 are the new pass.
  - The spec section is about 45 lines.
- **Encoder:** about 500 lines, `v4.rs`.
- **The control arm (RD steps) needs no decoder change at all.**

## Deviations
- **Speed measured on a busy GPU** (Blender rendering). Relative numbers only.
- **Encode times measured on a loaded machine** (load 20–120).
- **The ≤ 64-colour rule** was added after the first matrix showed graphics losing losslessness. Both runs are in the data.
- **The RD step search (`rd_q8`) became the main finding.** It is an encoder-only change, outside the brief's v4 scope, and is reported as such.
- **Two curve runs predate a fix that removed two extra RDO passes from v4 arms.** Control and W10 were affected equally; marked in the data.
- **Eye real detail** is Shroomies_05 f150–209, the 1920×1080 crop at (768,256) as W9. **Eye glow** is Shroomies_31 f100–159.
- **New prototype tooling:**
  - `FUZZ_EXTRA` seed directory for the fuzzer.
  - `ladder` and `curve` commands in `lmbx_quality`.
  - `w10_lab` (crop, graphics, ceiling).

## Needs Amrit
1. **Decide on v4 transform sizes.** Recommendation: drop. Real footage gains ≤ 0.07 dB at LMB7's bytes, for a format change and +17–24% decode time.
2. **Eye-test C37–44.** The w10 arm on real footage is mostly the RD step search. If you see the gain, approve a W11 to ship it as an encoder-only 0.7.x, with no format change.
3. **Optional:** a speed re-measure with Blender idle, only if v4 is kept.
