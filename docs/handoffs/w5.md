## What shipped
- v0.5.0 (tag pushed), commit 9a70d16. LMBX is frozen as bitstream v1 and fully specified in
  docs/LMBD.md §11 (implementable without our code).
- The pieces:
  - `core::lmbx`: the normative reference decoder.
  - `wgpu`: the compute decoder. Only the bitstream is uploaded; it goes through write_buffer or the
    0.3.0 staging belt.
  - `lmbd-enc::lmbx`: the encoder, ported from B1d, with rate control.
  - CLI: `encode-lmbd --profile lmbx --chroma 444|422halo --quality|--frame-bytes`, `compare --float`,
    and LMBX bench measures; probe, decode and verify work on LMBX.
  - Five CC0 conformance vectors with normative hashes; a fuzz target `lmbx`.
- Decisions recorded:
  - **LMBX-D1** (Cowork): an exact integer inverse transform. A 12-bit integer DCT basis with arithmetic
    shifts, proven inside i32; every validated input has one defined output.
  - **LMBX-D2** (Amrit 2026-10-11, option a): 4:2:2-halo + 4:4:4 as signalled modes, no 4:2:0.
- Prototype refusal: B2a / LMXS files (texFormat 0x10, magic "LMXS") are refused as Unsupported.
- LMB7 is untouched: its vectors are still byte-identical.

## Design decisions made here (measured, in the spec)
- **32x32 tiles, one rANS stream per plane per tile** (the prototype used 64x64, one stream per tile).
  - A/B at the same picture: +3.5% bytes, 2.2-2.4x faster GPU decode (`docs/data/w5-lmbx-tile-ab.txt`).
- **In-stream DC prediction**: 6-28% fewer bytes at equal quality.
  - The DC step is floored at 2 (Y/A) and 4 (Co/Cg) so residuals fit ±1023; the error is at most ¼–½ code
    value of the block mean.
  - The chroma step minimum is 2. A real bug found by measurement: the prototype's q=1 chroma clipped the
    DC at 4:2:2 and gave 21 dB.
- Quantiser map stored raw (4 bits per 8x8 block). One sparse rANS table per frame. Optional alpha plane.
  Any frame size (edge-replicated to tiles).
- GPU performance work (all still bit-exact):
  - the IDCT as generated straight-line WGSL — the biggest win, 15 → 6 ms per 16 layers;
  - parallel table expansion;
  - packed slot entries.
- Output: RGBA in quarter code values (10-bit). 8-bit `(v+2)>>2`; the GPU path renders 8-bit.

## Validated (numbers per claim; data in docs/data/w5-*)
- Conformance: 12 vector frames hash to their sidecars, on the CPU both parallel and sequential.
  - GPU == CPU exactly on all 12 frames plus 36 hostile frames (random, empty and reversed streams),
    through both write_buffer and the staged upload.
  - The encoder re-encodes the vectors byte-identically at 1, 3 and 8 threads.
  - Tile independence holds for every plane.
- D1, integer vs float on the same bitstreams (`w5-lmbx-quality.txt`): the integer decode is equal or
  better in PSNR in every row (0 to +1.8 dB), and SSIM is within 0.001.
  - Metrics say integer is not visibly worse; Amrit's eye is pending.
- Quality at matched size (one frame per content; the better chroma mode shown):

  | Content | LMBX vs LMB7, at LMB7's size | LMBX vs HAP Q, at HAP Q's size |
  |---|---|---|
  | gradient over black | +4.8 dB | +4.6 dB |
  | film grain | +6.9 dB | +8.3 dB |
  | synthetic alpha | +5.9 dB, alpha +8 dB | +10 dB |
  | detail (noise) | +1.3 dB (444) | +5.4 dB |
  | **flat hard-edged graphics** | **far worse**: LMB7 1.6 KB at 53.7 dB; LMBX floor 20 KB at 30.8 dB | −15.8 dB |
  | Shroomies glow | 444: +0.6 dB at 15% fewer bytes | 444: +3.6 dB |
  | **Shroomies real alpha** | **444: −1.4 dB RGB**, alpha +3.0 | −0.5 dB at 12% fewer bytes |

- Decode speed, idle GPU (Arena not running), two rounds (`w5-lmbx-speed-macstudio.jsonl`):
  - 16 x 1080p GPU: 92.6-92.8 steps/s (4:2:2), 73.6-74.2 (4:4:4).

  - 4 x 4K: 7.7 / 9.9 ms per step.
  - CPU 1080p: 6 ms per frame on all cores, 17-19 ms single-threaded; 16 layers at once 32-38 ms per step.
  - LMB7 for reference: 147-151 per-layer, 526-530 pipelined.
  - 4:4:4 decodes ~26% slower than 4:2:2.
- Chroma default: **4:4:4, provisional by measurement**. It is better on both real clips at equal bytes
  (+1.6 dB glow, +0.6 dB alpha); 4:2:2 wins on synthetic gradients (+0.5) and grain (+0.8).

## Deviations
1. The brief's step 6 says "LMBX 420-halo". It is built as 422-halo, per Amrit's LMBX-D2 ruling.
2. The eye clips are 2 s (60 frames) at 1080p, not full-length 4K, because LMB7 at its defaults takes
   ~30 min per 60 frames of 1080p. The alpha clip is downscaled from 4K.
3. LMB7-at-HAP-Q-size could not be formed (LMB7 is always smaller). LMBX was matched to each in turn;
   rate control is bounded by LMBX's best/coarsest quality, so some rows sit below budget.
4. Bitstream changes against the prototype (all measured, all in the spec): 32x32 tiles, a stream per
   plane, a raw quantiser map, DC prediction, chroma minimum step 2, DC step floor.
5. LMBX has no fixed frame layout, so the decode-into-staging and direct-view paths don't apply (they
   refuse clearly). Write_buffer and staged uploads work.
