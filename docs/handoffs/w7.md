# W7 — Can LMBX close its gap to LMB7 on graphics with alpha? (EXPLORE; nothing shipped)

## Answer in one line
**Yes, and by far:** the gap was the palette **index coding**, not alpha.
- With context-coded indices plus three small additions, LMBX codes both graphics cards **losslessly in fewer bytes than LMB7**.
- The 1080p eye clip is lossless on all 60 frames at **69% of LMB7's bytes**.
- The price is a **bitstream v3** and **17–33% slower GPU decode**, as prototyped.

## DIAGNOSE (before building; `docs/data/w7-lmbx-v3-ab.txt` §DIAGNOSE)
At LMB7's 5,204 B on the CC0 graphics+alpha card: 0.6.1 scores 43.77 dB shown, LMB7 46.66.

| Where the error is | 0.6.1 shown SE | LMB7 shown SE |
|---|---|---|
| partial-alpha pixels (0.24% of the frame) | **3.64 M (85.7%)**, all of it alpha error, 0 colour | 0.96 M |
| opaque pixels | 0.61 M | 1.22 M |
| by tile: 35 anti-aliased tiles (palette mode) | **3.68 M (86.8%)** | 1.12 M |
| by tile: 141 hard-matte tiles | 0.07 M | 0.78 M |

- **Mechanism:** a 17-level anti-aliased alpha ramp collapses to 2 levels (tile 289), even in tiles that have ≤16 colours.
- **Root cause:** at LMB7's bytes, 0.6.1 sits at its **rate floor** (q 600 = 4.75 KB stored), so it has no bytes for the edges.
  - 75% of that floor is palette index streams: 3.6 KB stored, of which ~1 KB is rANS start states.
  - Palette colours cost only ~10% of their raw size after Zstandard.
- **Index-coding study:** copy-left / copy-above / literal coding with 8 contexts cuts index bits by 62% (5,146 → 1,965 B on the card).

## Costs
- **GPU decode** (steps/s, two rounds, Arena running):

  | Clip | 0.6.1 | w7 best | Change |
  |---|---|---|---|
  | 16 × 1080p glow | 58.4 | 46.1 | −21% |
  | 16 × 1080p graphics | 128 | 85 | −33% |
  | 4 × 4K Shroomies | 96.7 | 75.4 | −22% |
  | 4 × 4K graphics | 148.6 | 123 | −17% |

  - As first built it was −29 to −45%. Two shader fixes recovered part of it: the table search is bounded to the alphabet, and the index rows sit in a chroma-plane scratch instead of private arrays.
  - What remains is the v3 format itself (−9% glow, −19% graphics, not yet profiled) and quad.
- **GPU == CPU:** bit-exact on 264 encoded v3 frames and 792 hostile ones; v1/v2 unchanged (20 + 68). BC7 tiles have no GPU decode (refused).
- **Encoder:** 1080p glow frame at q16: 0.15 s → 0.26 s (best), 0.34 s with every knob.
- **Size added:**
  - spec: 68 lines (`docs/w7-lmbx-v3-prototype.md`);
  - CPU decoder: ~330 lines;
  - GPU decoder: ~300 lines WGSL/Rust;
  - encoder: 634 lines (`w7.rs`).

## Recommendation (Amrit decides)
**Ship as LMBX v3:**
- context-coded palette indices — the one change that closes the gap;
- exact 17–64-colour palettes;
- edge alpha;
- quad sub-tiles.

That gives lossless graphics with alpha below LMB7's bytes. Before freezing:
- profile and cut the v3 format's GPU overhead (direct stream per tile, table expansion; candidate: 10–12-bit index tables);
- decide whether 16 × 1080p glow at 46 steps/s (vs 58) is acceptable.

**Optional:** DCT colour + alpha palette (synthetic-alpha gain, neutral elsewhere).

**Drop:** escapes, direct colour + DCT alpha, alpha visibility weighting, lossy >16-colour palettes.

**BC7 tiles:** drop for graphics. But they gained +4.6 dB on the noise-like detail card, a separate question (cost: a WGSL BC7 decoder and a 2–4 minute BC7 encode per 1080p frame).

**If v3 is not wanted:** the encoder-only `allk+cb8` already beats LMB7 on plain graphics (+2.2 dB) in v2, but not with alpha.

## Deviations
1. **Synthetic contents re-created:** W5's scratch generator is gone, so alpha / grain / detail are CC0 re-creations with fresh LMB7 budgets. Shroomies and card budgets match W6b to the byte.
2. **One prototype bitstream for every bitstream candidate:** the v3 prototype carries them all, switchable, so each was measured alone and combined.
3. **Encode-time ratios of 1.0 for natural content are approximate:** natural content's coarse quantiser steps left some arms under budget.
4. **GPU decode was built only for non-losing candidates:** BC7 lost on graphics, so it got no GPU decode.
5. **Eye clips via ffmpeg:** written with ffmpeg `prores_ks` 4444xq (`ap4x`, the same format as earlier rounds).
6. **Branch test edit:** the refusal test's "future version" moved 3 → 4 on the branch, because v3 now parses there.
